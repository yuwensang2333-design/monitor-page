## 一、项目概述

### 1.1 背景

高速公路机电系统由交换机、隧道 PLC、火灾报警、电话广播、NVR、摄像机、情报板、电力监控、
对讲终端等大量异构设备组成，分布在收费站、隧道、门架、服务区等场景。设备品牌与协议各异，
运行状态分散在多套子系统里，值班人员难以在第一时间判断“哪一类设备出了问题、影响多大、
需要谁去处理”。

### 1.2 目标

建成一屏可视的机电设备运行状态监测平台，实现三件事：

1. **看得全**：设备总量、健康度、告警分布一屏掌握，避免多系统切换。
2. **看得快**：按设备类别聚合告警数量，异常类别一眼可见（红色高亮）。
3. **看得准**：告警等级、持续时长、所属设备与描述同时呈现，直接支撑派单。

### 1.3 建设范围

| 范围 | 说明 |
| --- | --- |
| 本期包含 | 总览大屏、告警监测页两个页面及其实时刷新机制（原型阶段使用模拟数据） |
| 本期不含 | 设备台账维护、工单流转、历史报表导出、移动端 |
| 数据来源 | 原型内置模拟数据源；正式版对接综合监控平台接口与消息中间件 |

## 二、使用角色与使用场景

| 角色 | 使用场景 | 关注重点 |
| --- | --- | --- |
| 监控中心值班员 | 大屏常驻值守，7 × 24 小时盯屏 | 告警等级、新告警、告警持续时长 |
| 机电运维班组 | 接到派单后定位设备与类别 | 设备编码、安装位置、故障描述 |
| 路段管理人员 | 周期性查看设备健康水平 | 健康度趋势、类别告警数量、告警率 |

典型流程：大屏发现告警 → 切到告警监测页定位类别 → 查看告警明细中的设备编码与描述 →
联系对应班组处理 → 处理完成后该条告警从当前告警列表消失。

## 三、术语与告警等级定义

| 等级 | 含义 | 典型触发场景 | 展示色 | 处理要求 |
| --- | --- | --- | --- | --- |
| 紧急 | 直接影响通行安全或业务中断 | 摄像机离线、卷帘门状态异常、消防水压异常 | 深红 `#ff4a5f` / 深红底 `#7d1b23` | 立即响应，5 分钟内确认 |
| 重要 | 设备主要功能异常，存在劣化趋势 | PLC 获取数据失败、NVR 通道异常、电力监控越限 | 橙 `#ff8b34` | 30 分钟内响应 |
| 普通 | 一般性异常，不影响当前业务 | 摄像机取流失败、情报板通信超时、车道指示灯通信异常 | 蓝 `#4aa3f0` | 当日处理 |
| 提示 | 提醒类信息 | 维护提醒、阈值接近 | 灰蓝 `#8fa3bb` | 观察即可 |

关键指标口径：

| 指标 | 口径 |
| --- | --- |
| 总设备数 | 纳入监测的机电设备总数（原型示例 1081） |
| 正常设备数 | 当前无未恢复告警的设备数 |
| 告警设备数 | 当前存在未恢复告警的设备数 |
| 告警率 | 告警设备数 ÷ 总设备数（原型示例 16.74%） |
| 设备健康度 | 设备最近一次健康评估得分（0–100），按类别取均值 |
| 告警时长 | 从首次发生到当前的时间长度，展示为 `HH:MM:SS` 或“x小时x分x秒” |

## 四、信息架构

```
高速公路机电系统运行状态智能监测平台
├─ 总览大屏 index.html ────────────── 面向上级汇报与中心值守
```

「总览大屏 ›」回到大屏。

## 六、交互与状态规范

### 6.1 实时刷新节奏（原型演示值，正式版以接口能力为准）

| 内容 | 频率 | 方式 |
| --- | --- | --- |
| 告警时长 | 1 秒 | 前端本地累加 |
| 新告警 / 告警恢复 | 事件触发（原型 14–16 秒模拟一次） | WebSocket 推送 |
| 关键指标、告警等级占比 | 随告警变化同步刷新 | 前端重算 |
| 设备健康度 | 6 秒 | 接口轮询 |
| 过去 7 天统计 | 5 分钟 | 接口轮询 |

### 6.2 视觉与动画

| 元素 | 规范 |
| --- | --- |
| 页面进入 | 数字滚动 1.2–1.8 秒（缓出曲线），条形图宽度过渡 1.1 秒 |
| 新告警 | 0.9 秒左滑淡入 + 高亮，随后回落为常态底色 |
| 拓扑链路 | 虚线流动动画，2.6 秒一个循环 |
| 卡片数字变化 | 0.7 秒放大回弹 |
| 悬停 | 背景提亮或卡片上浮 2px，过渡 0.22 秒 |

| 场景 | 表现 |
| --- | --- |

## 八、数据模型与接口约定

### 8.1 设备对象（Device）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 设备唯一编码，如 `XBLJLS_2_PLC12` |
| `name` | string | 设备名称 |
| `categoryKey` | string | 类别标识：`switch` / `plc` / `fire` / `camera` … |
| `categoryName` | string | 类别名称，如「交换机」 |
| `location` | string | 安装位置：收费站 / 隧道 / 门架 / 服务区 |
| `status` | enum | `normal` 正常、`alarm` 告警、`offline` 离线 |
| `health` | number | 健康度 0–100 |
| `lastReportAt` | datetime | 最后一次数据上报时间 |

### 8.2 告警对象（Alarm）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 告警唯一标识 |
| `name` | string | 告警名称，如「Nvr_通道异常」 |
| `deviceId` / `deviceName` | string | 关联设备编码与名称 |
| `categoryKey` / `categoryName` | string | 设备类别，用于卡片聚合 |
| `level` | enum | `紧急` / `重要` / `普通` / `提示` |
| `description` | string | 告警描述，含阈值与现象 |
| `startAt` | datetime | 首次发生时间 |
| `duration` | number | 持续秒数（前端按秒累加） |
| `status` | enum | `active` 未恢复、`confirmed` 已确认、`recovered` 已恢复 |

### 8.3 接口清单（建议）

| 方法 | 路径 | 用途 | 对应前端元素 |
| --- | --- | --- | --- |
| GET | `/api/overview/summary` | 关键指标 | 顶部四项 KPI |
| GET | `/api/overview/device-health` | 设备健康度 | 设备健康度条形图 |
| GET | `/api/overview/device-count` | 设备分类数量 | 设备分类数量图 |
| GET | `/api/overview/topology` | 网络拓扑节点与链路 | 新博高速监控网 |
| GET | `/api/overview/alarm-levels` | 告警等级分布 | 告警等级环形图 |
| GET | `/api/overview/week-alarms` | 近 7 天类别告警量 | 过去 7 天条形图 |
| GET | `/api/alarms?status=&level=&page=` | 告警列表 | 两页的告警列表 |
| GET | `/api/alarms/stats` | 各类别告警计数 | 告警页 22 类卡片 |
| POST | `/api/alarms/{id}/confirm` | 确认告警 | 后续「确认」操作 |

### 8.4 实时推送消息示例

```json
{
  "type": "alarm.new",
  "ts": "2026-10-15T22:25:03+08:00",
  "data": {
    "id": "AL2026101500225",
    "name": "摄像机_离线告警",
    "deviceId": "CA42",
    "deviceName": "九连山隧道CA42",
    "categoryKey": "camera",
    "level": "紧急",
    "description": "摄像机与平台通信中断，最后在线时间为 08:12:04",
    "startAt": "2026-10-15T21:40:00+08:00",
    "status": "active"
  }
}
```

消息类型：`alarm.new`（新告警）、`alarm.update`（等级或描述变化）、`alarm.recover`（已恢复）、
`device.health`（健康度变化）。
